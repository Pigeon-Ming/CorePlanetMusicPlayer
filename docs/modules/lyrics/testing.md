# 歌词模块测试

歌词初版目前包含代码级开发者自检和需要在真实文件环境中执行的人工测试。

## 开发者自检

开发者测试控件提供“验证歌词核心逻辑”按钮，入口位于：

- [`TestControl.xaml`](../../../CorePlanetMusicPlayer6/Controls/Dev/TestControl.xaml)
- [`TestControl.xaml.cs`](../../../CorePlanetMusicPlayer6/Controls/Dev/TestControl.xaml.cs)

当前检查内容：

- 相同时间标签的双行翻译合并。
- 使用 `「」` 的行内翻译。
- 一行多个时间标签。
- 一至三位小数时间精度。
- 只有元数据的文本不被识别为同步歌词。
- 应用缓存、外部、内嵌和在线歌词的来源优先级。
- 无效文档排除。
- 重复来源去重。
- 播放器首选文档选择。

这些检查不访问真实音频文件，也不替代平台兼容性测试。

## LRC 人工检查

- Windows、Unix 和单回车换行。
- UTF-8 BOM。
- 空行和只有元数据的文件。
- 多时间标签。
- 相同时间的双行翻译。
- 行内 `「翻译」`。
- 多条不同翻译合并。
- 翻译与原文相同的去重。
- 非法或缺失时间标签。

## 外部歌词人工检查

- 与音频同名的 `.lrc` 能被发现。
- 同名匹配优先于正则匹配。
- `{FileName}` 正则占位符正确转义。
- 无效正则给出错误，不阻断其他来源。
- 正则超时被捕获。
- 多个正则候选的结果保持确定性。
- 歌词文件新增、重命名或删除后，重新加载结果正确。
- 音乐库授权失效时不崩溃。
- 只读文件写入失败后可以选择应用缓存。
- 非 UTF 编码文件给出可理解的错误。

## 内嵌歌词人工检查

应选取项目实际支持的不同音频格式，分别验证：

- 无歌词标签。
- 已有歌词标签。
- 写入新歌词。
- 覆盖旧歌词。
- 写入后重新读取内容一致。
- 文件被播放器或其他程序占用。
- 文件只读。
- 格式不受 TagLibSharp 支持。
- 音频或标签损坏。
- 临时文件失败后原文件保持可用。

测试时应特别关注旧 Windows 版本和目标 Windows Phone 环境。

## 保存链路人工检查

- 外部歌词默认写回原文件。
- 外部歌词可以显式写入内嵌标签。
- 外部歌词可以显式保存为应用缓存。
- 内嵌或在线来源保存时出现目标选择对话框。
- 文件写入失败时仅在用户确认后回退数据库。
- 每首歌曲最多存在一份应用缓存。
- 成功写入外部或内嵌歌词后清除旧应用缓存。
- 恢复来源歌词后重新执行正常优先级选择。
- 保存非播放器首选来源时提示信息正确。

## UI 人工检查

- 切歌后显示对应歌曲和歌词。
- 播放位置变化时当前行正确高亮。
- 当前行保持在视口约 40% 的位置。
- 长原文和长翻译自动换行后定位正确。
- 鼠标滚轮、触摸或拖动后暂停跟随。
- 暂停跟随时高亮仍继续变化。
- 点击恢复按钮后回到当前歌词。
- 点击歌词行后播放位置正确跳转并恢复跟随。
- 快速切歌时旧加载结果不覆盖新歌曲。
- 页面反复加载和卸载后没有重复事件响应。
- 编辑器切换来源不会改变播放器全局优先级。
- 有未保存内容时，重新加载、切歌和切换来源都会要求确认。

## 当前验证状态

歌词核心解析、来源排序和项目编译已经完成代码级验证。真实文件权限、TagLibSharp 格式支持、文件占用、旧平台行为和完整 UI 交互仍应在目标设备上执行人工验证。
