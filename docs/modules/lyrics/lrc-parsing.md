# LRC 解析

LRC 解析由 [`LrcParser`](../../../CorePlanetMusicPlayer.Services/Lyrics/LrcParser.cs) 完成，并通过 `ILyricParser` 接口供业务服务使用。`LyricParserCollection` 为以后增加其他歌词格式保留了组合入口，当前只注册 `LrcParser`。

## 支持的时间标签

当前支持：

```lrc
[01:23]Text
[01:23.4]Text
[01:23.45]Text
[01:23.456]Text
```

小数部分转换规则：

- 一位表示百毫秒。
- 两位表示十毫秒。
- 三位表示毫秒。

分钟支持一至三位，秒数限制为合法的秒范围。

## 多时间标签

一行可以包含多个时间标签：

```lrc
[00:10.00][00:20.00]Repeated line
```

解析后会生成两条内容相同、时间不同的 `LyricLine`。

## 文本规范化

解析前会：

- 将 `\r\n` 和单独的 `\r` 统一为 `\n`。
- 移除文本开头可能存在的 UTF BOM。
- 移除整个文档首尾的空白。

不带时间标签的行不会转换成同步歌词，因此 `[ar:]`、`[ti:]`、`[al:]` 等元数据不会进入歌词列表。

## 翻译格式

### 相同时间的双行翻译

```lrc
[00:03.89]Original
[00:03.890]翻译
```

两个时间标签都会转换为相同的毫秒时间。解析器将第一个有效文本作为原文，其余同时间文本作为翻译。

### 行内翻译

```lrc
[00:03.89]Original 「翻译」
```

仅当文本以 `」` 结尾，并且前面存在有效原文和有效翻译时，才会拆分行内翻译。普通正文中不完整的括号不会被误拆。

## 临时片段与合并

解析器不会在读取单行时立即生成最终 `LyricLine`，而是先生成内部歌词片段，记录：

- 时间
- 原文候选
- 行内翻译候选
- 在原始文件中的出现顺序

所有片段解析完成后：

1. 按时间排序。
2. 相同时间按照原始出现顺序排列。
3. 按时间分组。
4. 选择原文。
5. 合并并去重翻译。
6. 生成连续的歌词行索引。

这一步是支持相同时间双行翻译和一行多个时间标签的基础，也避免依赖 `List.Sort` 的非稳定排序行为。

## 翻译合并规则

- 第一个非空文本作为原文。
- 相同时间的其他文本作为翻译候选。
- 行内翻译也加入翻译候选。
- 与原文完全相同的翻译不会重复保存。
- 完全相同的翻译只保留一次。
- 多条不同翻译使用换行连接到 `TranslationText`。

## 当前限制

- 不解析非同步纯文本歌词。
- 不解析逐字时间标签。
- 不保存 LRC 元数据标签。
- 不尝试自动判断语言。
- 相同时间出现多条独立原文时，后续文本会按照翻译处理。
